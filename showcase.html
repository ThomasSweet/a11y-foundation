CSS showcase

The same idea, looking forward: modern CSS worth knowing, grouped by where it stands across the current versions of Chrome, Firefox, and Safari — based on Interop and BaselineBaselineThe web platform’s shared support signal: “widely available” (stable in all engines for ~30 months), “newly available” (everywhere, but recent), “limited availability” (not yet in every engine). The showcase tiers borrow its exact vocabulary.. Everything is written as a progressive enhancement, so unsupported demos degrade instead of breaking. Every snippet here also ships in the agent skill, generated from the same registry, with a check in CI that fails when the two disagree. By the end: which modern CSS features carry an accessibility payoff, and how safely each one ships today.

Container queries

Components respond to the space they actually get instead of the viewport. Together with auto-fit/minmax grids, this replaces most media queries — use the slider to resize the container, not the window.

Container query units

The other half of container queries: cqi units inside clamp() scale type and spacing in proportion to the component’s own space, with no breakpoints and no broken in-between states. Type needs a rem term in the middle value: with cqi alone, zoom and the reader’s font size may not make the text any bigger.

Accessibility payoff:Spacing in cqi gives text more room in a narrow container, even at 400% zoom; for type, a rem term in the middle and a maximum within 1.5 times the minimum let zoom double the text in every engine.

Accessibility payoff::has() styles states the DOM already knows — no JS class-toggling that can drift from the real, announced state.

content-visibility

content-visibility: auto lets the browser skip rendering sections until they approach the viewport, so long pages paint fast with no virtual-scrolling JS. The accessibility story is what skipping keeps: unlike display:none, skipped content stays in find-in-page, the tab order, and the accessibility tree. Prove it with your own browser — search the pane for “cardamom” and the browser finds it inside a section it never rendered; search “saffron” and the display:none appendix stays invisible. contain-intrinsic-block-size keeps the scrollbar honest while sections are skipped. One cost to plan for: the same containment clips a focus ring at the section’s padding edge, so a section with focusable children needs padding of at least the ring width plus its offset.

Accessibility payoff:Fast first paint without hiding anything from anyone: skipped sections stay findable and announceable — and a lighter main thread is assistive-tech responsiveness, because the accessibility tree is walked on that same thread.
